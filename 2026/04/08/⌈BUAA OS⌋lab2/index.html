Thinking 2.4

  • 从虚拟内存和多进程操作系统的实现角度，阐述ASID 的必要性。

  • 请阅读 MIPS 4Kc 文档《MIPS32® 4K™ Processor Core Family Software User’s Manual》的 Section 3.3.1 与 Section 3.4，结合 ASID 段的位数，说明 4Kc 中可容纳 不同的地址空间的最大数量。

  • ASID的必要性在于，多进程操作系统中各个进程拥有独立的虚拟地址空间，不同进程可能会使用相同的虚拟地址。如果没有ASID，每次进程切换都必须彻底清空TLB缓存，防止新进程错误访问到旧进程的内存，这会导致巨大的性能损耗。加入ASID作为进程标识后，不同进程的映射可以安全地共存于TLB中。进程切换时只需更新当前的ASID值即可，无需清空TLB，在保证内存隔离的同时大幅提升了运行效率。
  • 根据MIPS 4Kc文档，ASID字段存储在EntryHi寄存器的最低8位中。由于ASID占据8个比特位，因此4Kc处理器最多可以容纳2的8次方，也就是256个不同的地址空间。

Thinking 2.6

请结合 Lab2 开始的 CPU 访存流程与下图中的 Lab2 用户函数部分，尝试将函数调用与CPU访存流程对应起来，思考函数调用与CPU访存流程的关系。

  1. TLB 命中： 纯硬件行为。CPU 经 MMU 查询 TLB 成功，直接访存，不涉及任何软件函数调用。
  2. TLB 缺失重填： 硬件查询 TLB 失败，触发异常。调用 do_tlb_refill（汇编入口） → _do_tlb_refill → 调用 pgdir_walk 遍历两级页表查找映射。查找到映射后，执行 tlbwr 指令将页表项填入硬件 TLB，CPU 重新执行访存。
  3. 缺页分配： 若 pgdir_walk 发现两级页表中也无映射记录。触发惰性分配，调用 page_alloc 分配物理页 →→ 调用 page_insert 将新映射写入页表。
  4. 维护一致性： 当 OS 主动改变内存映射（如 page_insert 更新或 page_remove 拆除映射）时。必须同步调用 tlb_invalidate →→ tlb_out，强制硬件清空对应的旧 TLB 表项，防止 CPU 读到脏数据。

二、难点分析

本次实验的难点主要体现在以下几个方面：

  • 地址空间的转换与界限区分。实验中频繁交织着物理地址、用户虚拟地址和内核虚拟地址。深刻理解MIPS内存布局，并准确选择物理地址转换宏或内核虚拟地址转换宏是极易出错的盲区。
  • 复杂链表宏的底层机制理解。不熟悉宏展开后的实际指针走向和结构体成员对应关系，会导致参数传递错误，造成链表断裂或死循环。
  • 两级页表的动态维护机制。理解页目录和二级页表在内存中的层级关系太难了。
